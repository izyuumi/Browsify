Links keep opening in the wrong Chrome profile.

Updated September 12, 2026. Written by the developer of Browsify, which is one of the four fixes below. The other three are free.

Why it happens

macOS has exactly one default web browser. When Slack, Mail, Calendar, or any other app opens a link, the system hands it to that browser app and stops there. It has no idea that Chrome contains a work profile and a personal profile. Chrome then picks a profile itself.

On the Mac, Chrome opens external links in the last regular profile you used, not the window in front of you. This changed in Chrome 68; before that, links went to the frontmost window. Google's profile help page does not document either behavior, so the clearest public record is the ChromeBuddy README, which cites the Chromium tracker discussion. Treat the version number as community-documented rather than official.

The practical result: you answer a personal email, click a work link from Slack, and it lands in the personal profile where you are not signed in.

Fix 1: keep the right profile as the last one used (free)

Chrome uses the last regular profile that had focus. If you click into a work-profile window before clicking a work link, the link follows. This costs nothing but attention, and it fails the moment you forget.

Fix 2: launch a profile directly with a flag (free, manual)

Chrome accepts a command-line profile selector. The value is the folder name on disk, not the profile's display name. To find it, open the profile in Chrome, visit chrome://version/, and read "Profile Path". The last path component is the folder name, usually "Default" or "Profile 1".

open -na "Google Chrome" --args --profile-directory="Profile 1" "https://example.com"

This is useful in scripts and shortcuts. It does not intercept links other apps open, so on its own it does not fix the original problem. Every router below uses this same flag under the hood.

Fix 3: Finicky (free, open source, config file)

Finicky becomes your default browser and reads a JavaScript config file. You write rules that match a URL or the app that opened it and send the link to a browser or profile. It is the right choice if you like editing config files and want no GUI.

Fix 4: a link router with a settings window

Browsify, Velja, Choosy, and OpenIn all do what Finicky does with a native settings window. See the comparison for prices, minimum macOS versions, and feature differences. The Browsify steps:

  1. Install Browsify from the Mac App Store and open it.
  2. Click "Set as Default Browser" on the welcome screen. macOS shows a confirmation; accept it. You can also do this in System Settings, Desktop & Dock, "Default web browser" (Apple's steps).
  3. Grant Browsify read access to Chrome's profile folder when asked. It reads Chrome's profile list so it can show profile names instead of folder names.
  4. Add a rule. Match a domain such as "github.com", a URL pattern, or a source app such as Slack. Set the target to "Google Chrome, Work".
  5. Add a second rule for the personal side, or leave it unmatched. When no rule matches, Browsify shows a picker with one-key shortcuts, and you choose.

Rules are evaluated top to bottom; the first match wins, so put specific rules above broad ones.

What none of these fix

A link clicked inside a browser stays in that browser. Chrome does not tell macOS about it, so no default-browser app, Browsify included, ever sees it. If you click a link in a personal Chrome tab and want it in the work profile, the routers cannot intercept it. Velja, Choosy, and OpenIn ship browser extensions that add a toolbar button or right-click item to send a link back to the router; Browsify does not. For that case, use one of them, or right-click the link, copy it, and open it from Browsify's menu bar item.

Firefox, Brave, Edge, Vivaldi

The same design applies. Chromium-based browsers accept the same profile flag. Firefox uses named profiles, and routers support them with varying limits; Velja, for example, supports only Firefox's newer profile format. Safari profiles are only routable by OpenIn at the time of writing, because Safari has no equivalent launch flag.
